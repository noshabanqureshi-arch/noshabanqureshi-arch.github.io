# Square Social Studio — Customer Success Flow

Purpose: make the customer experience continue after a click or purchase instead of treating checkout as the end of the funnel.

## Principle
The full journey is:
**Discover → Learn → Trust → Act → Transform → Retain → Advocate**

Each paid offer must have:
1. clear access,
2. one first action,
3. a quick win,
4. support guidance,
5. a feedback moment,
6. an honest review/referral opportunity only after real use.

## Free 30 Content Ideas

### Before activation
- finished ZIP exists in private Dropbox,
- website landing page exists,
- $0 Payhip product still needs creation/testing,
- automatic mailing-list subscription remains OFF.

### After Payhip activation
Flow:
`/free/30-content-ideas/`
→ $0 Payhip product/order
→ protected ZIP delivery
→ `/free/30-content-ideas/thanks/` when a redirect/next-step link is available
→ choose five ideas
→ optional $27 Starter next step

The thank-you page is `noindex` and does not collect data.

## Post-purchase email sequence
Once permission/sender infrastructure is active, use the existing customer-success email sequence:
- access + first action,
- quick win,
- friction check,
- outcome/feedback,
- honest review/advocacy.

Transactional access emails and optional ongoing marketing permission must remain conceptually separate.

## Future course customer success
Do not open enrollment until:
- lesson media complete,
- captions/transcripts complete,
- learner access protected/tested,
- checkout tested,
- lesson completion path clear,
- support path clear,
- refund/access policy matches actual delivery.

Course completion is more important than adding more course inventory.

## Future Vault customer success
Do not open subscriptions until:
- first release is already loaded,
- next release is substantially prepared,
- delivery/member platform tested,
- Stripe sandbox subscription lifecycle tested,
- cancellation/access logic tested,
- billing support path clear.

Primary Vault retention metric: members actually using the monthly assets/system, not simply remaining subscribed by inertia.

## Done-for-You customer success
Application
→ fit review
→ agreement + first payment
→ structured 14-day onboarding
→ monthly Evaluate → Plan → Produce → Approve/Publish cycle
→ real-data reporting
→ quarterly fit/scope review
→ honest review/referral request only after enough delivered history exists.

## Advocacy rules
- Never pre-write a positive review for a customer to post as if it were their own words.
- Ask for honest feedback, not guaranteed praise.
- Get explicit permission before publishing a quote, business name, image, result, screenshot or UGC.
- Separate private product-improvement feedback from public-testimonial permission.
